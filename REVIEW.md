# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints):

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Used `minutes > 10` which fails R2 rule for inputs strictly more than 10 minutes (e.g. 09:40:01 IST resulted in 0 late minutes instead of 10). Also lacked IST timezone awareness and whole-second truncation (R1). | Passing `punch_in` at 09:40:01 for a 09:30 shift returned `late_minutes = 0` instead of `10`. | Truncated instants to whole seconds, converted `punch_in` to IST, computed total elapsed seconds `diff_sec`, and applied `late_minutes = diff_sec // 60` if `diff_sec > 600`. |
| 2 | `punch_in` (lines 100-104) | Missing employee lookup check; accessed `emp["shift_start"]` when `emp` was `None`. | Calling `/attendance/punch-in` with an unknown `emp_code` threw an unhandled Python `TypeError` (500 internal server error). | Added check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 3 | `punch_in` (lines 104-118) | Vulnerable to race conditions due to check-then-insert pattern (`find_one` followed by `insert_one`). | Two concurrent punch-in requests at the same millisecond created duplicate attendance log documents for the same employee and date. | Created a unique compound index on `attendance_logs.(emp_code, date)` and caught `DuplicateKeyError` to return HTTP `409`. |
| 4 | `list_employees` (line 93) | Incorrect pagination skip calculation `skip = page * page_size` and `total` count ignored the `department` query filter. Also lacked sorting by `emp_code`. | Requesting `page=1, page_size=20` skipped the first 20 records (returning items 21–40). Filtering by department returned the total collection size instead of filtered count. | Fixed skip to `(page - 1) * page_size`, computed `count_documents(q)`, and added `.sort("emp_code", 1)`. |
| 5 | `list_attendance` (lines 144-150) | Fetched all matching documents into Python memory and sorted in-memory using `docs.sort(...)`. | Fails scalability performance requirements on ~100,000 documents; causes high memory footprint and CPU latency. | Delegated sorting and pagination directly to MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 6 | `punch_in` date calculation (lines 103-104) | Used naive UTC date `ts.date().isoformat()` without checking overnight shifts (R1). | Overnight shift (e.g., 22:00–06:00) punch-in at 02:30 IST on 2026-07-07 assigned the record to 2026-07-07 instead of previous day 2026-07-06. | Implemented `compute_attendance_date` with IST offset and overnight logic (`shift_end <= shift_start` check). |
| 7 | `compute_work_hours` & `compute_overtime` (lines 40-47) | Standard `round(..., 2)` used Python banker's rounding instead of half-up (R4/R8). `compute_overtime` failed for overnight shifts due to naive date replacement. | Rounding 2.125 gave 2.12 instead of 2.13. Overnight shifts produced incorrect or negative overtime values. | Replaced rounding with `Decimal` `ROUND_HALF_UP`. Recomputed overtime using shift end on the next calendar day for overnight shifts. |
| 8 | Timestamp & ID serialization (lines 84, 119-120) | Included internal `_id` / `id` fields in responses and failed to serialize BSON datetimes into integer epoch milliseconds. | API response bodies contained string `id` fields and raw BSON datetime objects, violating `openapi.yaml`. | Removed `_id`/`id` from responses and serialized all BSON datetimes (`created_at`, `punch_in`, `punch_out`, `at`) to epoch ms. |
| 9 | `GET /health` (lines 72-74) | Returned `{"status": "ok"}` unconditionally without verifying database connectivity. | Returning 200 when MongoDB is offline violates the readiness probe contract. | Added `db.command("ping")` inside a try-except block, returning HTTP 503 when ping fails. |
| 10 | Input validation & timestamp bounds (lines 63-66) | Accepted invalid, float, string, or out-of-range timestamp formats without returning 422. | Passing `punched_at: 1000` (seconds instead of ms) or `"invalid"` was accepted or caused unhandled errors. | Added strict Pydantic field validators `validate_epoch_ms` requiring integers between `100000000000` and `4102444800000`. |

---

### Non-Defects Examined
1. **Pydantic Model Schema Types**: Verified `EmployeeIn` / `EmployeeCreate` schema field validations. Shift time strings regex `^([01]\d|2[0-3]):[0-5]\d$` were correct, but `shift_start != shift_end` validation was missing and added.
2. **PyMongo MongoClient Configuration**: Evaluated whether creating a single global `MongoClient` instance at startup is acceptable. Confirmed it is standard practice in FastAPI with PyMongo, as `MongoClient` handles connection pooling internally.
